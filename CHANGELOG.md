# Changelog

All notable changes to this project are recorded here. The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/). The project has no tagged releases yet, so everything is under **Unreleased**. Entries reference pull requests on `hixam001/battle-it-out`; dates are the merge dates.

## [Unreleased]

### Added

- **Worker and job queue outside the web process (BIO-EPIC-03, SRD-007; CN-017):** `backend/work_queue/`: a durable queue (one live job per key, claim token and renewed lease, takeover of a dead worker's job, retry with growing waits, `dead` plus incident and alert at the cap, `revive`), a worker loop and a command-line worker (`python3 -m backend.work_queue.service`). Two job kinds carrying ids only: the upload check of a stored version and a started round. An inconclusive check is retried, never blamed on the participant; a paused round finishes its job; trial and tournament games share one host lock. 53 tests (52 unit on Python 3.12 to 3.15; one real run with the worker as a separate process: two uploads checked, then a final played with real sandboxed games), 29 deliberate breakages all caught. No API or scheduler yet, one host only, no container.
- **Submission registry (BIO-EPIC-05, follows BIO-202; CN-016):** `backend/submission_registry/`: every upload is an immutable numbered version (read-only folder, SHA-256, usable as the match runner's `bots_dir`); the static check runs at upload; a worker claims a version, the trial verdict is recorded only for the live claim and the exact stored bytes; the highest valid version is active and a rejected, inconclusive or invalid one never displaces it; nothing is stored at or after the deadline (a later deadline reopens); captain-only upload, history and download for the team, the assigned Organizer and Admin (staff reads audited), `NotFound` for everyone else; write-once pins and `verify_pins`. 57 tests (55 unit, 2 real), 24 deliberate breakages. Library only: no endpoint, authentication, deadline storage or retention. Coverage matrix: SRD-051/052/053 DONE, SRD-054/056/057 PARTIAL.
- **Whole-tournament simulation (TC-05 partial; CN-015):** `backend/match_orchestrator/tests/test_tournament_e2e.py` plays a five-team tournament (odd, one crashing bot) on a pool from the real engine jar: byes, forfeit, tie-break maps, final on three maps, platform coin flip, winners advanced once, a repeat run changing nothing, replays stored, served by the access rule and purged at archive (checked on disk). Passed first time in about 48 s (needs `BIO_INTEGRATION=1`); four deliberate breakages caught. No product code changed. House bots, the qualification draw, the API and a service are still missing.
- **Map pools for tie-breaks (BIO-303/304; CN-014):** `backend/match_orchestrator/maps.py`: the engine's map catalogue (names and SHA-256 read from the pinned jar), pools with the played maps, 1 normal and 3 final tie-break maps pinned by hash and engine version, never edited, a tie-break map never also a played map; `create_bracket_from_pool` refuses a pool that no longer matches the engine and records the pool id. 34 tests (one on the real jar, one real final series on pool maps). Custom maps and tournament storage are not built.
- **Upload check: static check plus a trial match (BIO-202; CN-013):** `backend/submission_check/`: after `bot_validator`, the exact validated bytes play two games in the sandbox against a pinned reference bot (candidate on side A, then B); verdict `valid` / `rejected` (actionable reasons, fixed wording) / `inconclusive` (platform fault, nobody blamed); `may_activate` is true only for a valid verdict and the same SHA-256. 21 tests (2 real games). Library only: no upload endpoint or activation state yet.
- **Replay lifecycle (BIO-305; CN-012):** `backend/match_orchestrator/replays.py`: a vault for the engine's `.bc26` replays (hash and complete-gzip check on the way in, private files, ids that cannot leave the folder), the access rule (Admin all, Organizer assigned, participant registered tournaments; safe 404 without access, 410 after archive for everyone including Admin, `Unavailable` plus a staff incident for a missing or damaged file), `collect_bracket` to store every finished game's replay once, and archive = mark, delete, verify with `purge_pending` finishing a crashed or failed purge and every purge sweeping the folder again. Results, brackets and match records are untouched by a purge. 39 tests (1 real engine replay stored, served and purged); 8 deliberate breakages all fail the suite. Not done: endpoints, authentication, object storage, a player (DEC-10), notifications, backups.
- **Bracket, byes and the Organizer-started round runner (BIO-302/303; CN-011):** `backend/match_orchestrator/bracket.py`: one recorded random draw into a single-elimination tree, automatic byes for human teams (each in its own pair), rounds started by the Organizer only after the previous one is complete, matches played one after another as CN-010 series (last round = final with 3 tie-break maps), winners advanced exactly once and idempotently (closes CN-009's advancement gap), a paused game pauses its round. House bots are refused until DEC-06 is decided. 23 tests (22 unit, 1 real 3-team tournament). Not done: house bots, API and authorization, queue/service, tournament and map storage, qualification draw.
- **Requirements coverage matrix (`docs/REQUIREMENTS_COVERAGE.md`):** all 91 requirements (SRD-001 to SRD-070, BIO-REQ-01 to 23, BIO-NFR-01 to 12) with what Battlecode provides, status from code and tests (9 done, 28 partial, 49 not built, 5 deferred) and the development backlog that follows. Only 2 requirements are wholly provided by Battlecode; the rest are ours to develop.
- **Tie-break maps and the 50/50 coin flip (BIO-304; CN-010):** `backend/match_orchestrator/tiebreak.py` plays a match as a series of games. A game the engine decided by its own unseeded coin flip counts as tied (the engine's pick is ignored); a tied normal-stage match plays 1 predefined tie-break map, a tied final plays 3 (all three, in order); more map wins decides; still equal gives one `secrets` coin flip, stored once and never redrawn; a bot failure in any game forfeits the series; the series result advances once; `public_view` hides host details. Each game keeps the retry, incident and exactly-once rules of CN-009. 31 tests (28 unit, 3 real series); real example-bot final series ties on all four games and ends in a coin flip. Small orchestrator changes: a game of a series is not advanced alone, and a series game needs the engine's reason line. Not done: where tie-break maps come from, the qualification-cutoff draw (DEC-14), the audit log and the screen that shows the flip.
- **Match jobs with platform retry (BIO-306, core of BIO-301/302; CN-009):** `backend/match_orchestrator/` (library, standard library only): bot failure = forfeit with no retry; platform failure retried with the same map and submissions up to 10 attempts in total; at the cap the match is `paused`, an incident is stored and an alert function is called; duplicate jobs, second workers and late answers change nothing; a lost worker is replaced after its lease; advancement can be taken once. 34 tests (4 with real matches). **Not met:** a new random seed per retry (the engine's seed is not controllable). `launcher.PortBusyError` added.
- **Security review of the match runner (CN-008; `docs/SECURITY_REVIEW.md`):** self-review with real hostile-bot matches; `tests/test_security_review.py` (26 tests, 3 real matches) and hostile bots `oot_py`, `stop_py`, `badmethod_py`. Six findings, five fixed (see Changed); SR-06 and a human review stay open.
- **Structured match logs (BIO-206; CN-007):** every `run` writes `match-<stamp>.events.jsonl` (schema 1) with `trace_id`, `match_id`, `attempt` and per-event visibility (`all`, `team:A`, `team:B`, `staff`), plus `launcher.py logs --role participant|organizer|admin` to print what a role may read; a best-effort redactor removes host paths, e-mail and IP addresses and secret-looking text (`backend/match_runner/match_log.py`, 36 new tests, 4 of them real matches). Who may read what is an engineer's default, not an approved rule.
- **Failure classification (BIO-205; CN-006):** a bot whose process dies mid-game (`os._exit`, segfault, SIGKILL, leaving early) now loses (`bot_crash`) instead of being reported as a platform failure; the engine server hanging up first, a runner that never started, and the match timeout stay `platform_failure`. The decision uses what the host-side router sees (which side closed the connection first), not the runner's log. Results carry `outcome` (`completed`, `bot_failure`, `platform_failure`) and crash `evidence`. New: `tests/test_failure_classification.py` (24 tests, 8 with real matches including a killed engine server) and four crashing test bots.
- **Bot execution limits and sandbox (BIO-203/204; CN-005):** one runner process per team, each in its own bubblewrap sandbox (no network, read-only root, only its own bot folder, seccomp denylist, optional cgroup limits), joined to the engine server by a host-side `Router` (`sandbox.py`); `guard.py` (wall-clock watchdog for turns and start-up, memory check, rlimits, usage measurements, uncaught-exception counts); `limits.provisional.json` (**interim profile, not benchmark-approved**, DEC-04); automatic `normal` / `bot_violation` / `platform_failure` classification in the launcher that never trusts the team named inside a record; hostile test bots (`hang_py`, `hang_init_py`, `memhog_py`, `allocbomb_py`, `escape_py`, `forge_py`) and 36 unit plus integration tests (51 with the launcher tests); `docs/CHANGE_NOTICES.md` CN-005 (decisions taken by the engineer under owner delegation).
- **License and notices (CN-003):** root `LICENSE` (AGPL-3.0-only, same text as the Battlecode scaffold), SPDX identifiers on our source files, `THIRD_PARTY_NOTICES.md`, `docs/LICENSING.md` (what each Battlecode component declares, AGPL obligations, open items), and a dated modification notice in the one edited scaffold file.
- **Bot policy and validator (CN-004):** `docs/BOT_POLICY.md` and `backend/bot_validator/` (policy generated from the engine, validator with error and warning codes, 13 tests including an agreement test against the real engine runner and a drift check).

### Changed

- **Security fixes (CN-008):** (1) a bot could send engine calls during the other team's turn and so change who won a match or make the victim forfeit; the router now accepts a call only from the runner whose turn it is. (2) A bot could freeze its own process and its guard and turn a loss into a retryable `platform_failure`; the router now has its own response deadline and charges the silent team (`runner_unresponsive`). (3) An engine method number that does not exist crashed the server and was a `platform_failure`; it is now refused and charged (`protocol_violation`). (4) The bot validator no longer follows symlinks, blocks on FIFOs, reads more than 2 MiB or crashes on deeply nested source. (5) Team folder names must be plain names.
- **Security fix (CN-007):** a bot could forge the engine's own log lines through `log(...)` and so change its match's winner or reason, or force a `platform_failure` (and a replay) on a match it was losing. The router now rebuilds every runner frame and marks continuation lines in all text, a malformed frame ends that team's connection, and the launcher's parsers are anchored and take the last match. Frames reach the engine as canonical JSON (same content).
- `launcher.py run` now runs each team in its own sandboxed process with the limits profile **by default** and stops the Java server shortly after a runner dies. The JSON summary gains `classification`, `loser`, `winner_by_forfeit`, `violation`, `usage` (per team and per process), `router`, `sandbox`, `cgroup` and `limits_profile`; `runner_exit` is now per team and the runner log is split (`runner-A-*.log`, `runner-B-*.log`). `--no-sandbox`, `--no-limits`, `--no-cgroup` and `--require-cgroup` exist.
- **Behaviour change (CN-005 D4):** bots of the two teams no longer share Python module state or the global `random` stream. The seeded example bot played against itself now ends in round 1310 with the engine's coin flip (winner varies between runs) instead of round 1290 with an A win.
- Jira/requirement ID scheme: PRD scope items renumbered from the duplicate `BIO-101..110`, `BIO-201..208`, `BIO-301..305` to `BIO-REQ-01..23`; PRD and test plan bumped to v1.1, and test-plan Jira references now point only at defined task keys or epic IDs (#1, 2026-11-05).

### Removed

- Java bot support (CN-002): the Java example bot `src/examplefuncsplayer/RobotPlayer.java`, the Java placeholder test, the Java defaults in `gradle.properties`, and the Java options of the launcher. The Java engine server is the game engine and stays.
- Agent and skill files (`.claude/skills/`, `.claude/agents/`, `.agents/`, `skills-lock.json`) are no longer tracked by git; the files stay on each developer's machine. Reinstall locally with the install commands recorded in `handoff.md` (#4, 2026-11-24).

### Known issues

- The engine package officially supports only Python 3.12 (`Requires-Python <3.13`). Python 3.12 to 3.15 pass our tests through `runner_entry.py`; this is unsupported by the engine's authors and was tested on Linux x86_64 only.
- The engine's bot sandbox allows `open`, attribute-walk escapes and infinite loops; it offers no wall-clock or CPU limit for pure Python code. The validator only warns about them (same policy as Battlecode). The launcher's per-team sandbox, guard, seccomp filter and cgroup limits contain these on the host, but the numeric limits are an interim profile and no independent security review has been done (`docs/TECHNICAL_DOCUMENTATION.md` section 3.6).
- The engine's tie-break ("coin flip") is not seeded from anything the project controls, so identical runs can have different winners; TC-04's "retry with a new random seed" needs an engine-side seed.
- The Battlecode Java engine declares no license; written confirmation is needed from the Battlecode team (`docs/LICENSING.md`).
- The scaffold's Gradle task for Python bots fails on Linux as shipped (wrong `python3` from `PATH`; `--new-process` start-up deadlock; missing class directory now that Java bots are gone). Use the launcher.
- The only automated test is a placeholder (`1 + 1`); the scaffold's Python `verify` checks only for the text `def turn():`.
