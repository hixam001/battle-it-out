# Native Python bundles (CN-028; BIO-509/510)

The owner selected Python multi-file bots and curated dependencies first;
additional languages follow compatibility work. Existing `bot.py` uploads keep
their API and SHA-256 semantics. An explicit ZIP upload adds flat Python modules
while keeping `bot.py` and top-level `turn()` as the entry point.

The existing engine already reads every immediate `.py` file into its module
map; its existing module loader resolves these before its ordinary allowed
imports. No engine/host import policy or sandbox mount is widened.

Example upload ZIP:

```text
bot.py
strategy.py
requirements.json  # optional: {"biohelpers":"1.0.0"}
```

Only unique flat module filenames are accepted. No symlinks, devices, directory
entries, traversal, nested packages, relative/cyclic imports, user package
installation or custom runtime images. Existing engine import names and curated
module names cannot be shadowed. ZIPs are read in memory with bounded member and
expanded-byte limits, never extracted to a participant-selected path.

Interim caps: 32 input files and 256 KiB including expanded curated source and
metadata. They are engineering ceilings, not benchmark-approved product limits.
The initial catalogue is `biohelpers` 1.0.0, a project-maintained, pinned source
module with Manhattan/Chebyshev distance and clamp helpers (project AGPL-3.0-only
SPDX notice preserved). No arbitrary third-party dependencies are claimed.
`requirements.json` must use exact published names/versions; the catalogue route
publishes their SHA-256. Operator-curated source is copied into each immutable
submission snapshot.

`bundle.json` is generated by the platform. The aggregate digest covers sorted
filenames and every file's SHA-256, including dependency metadata. Static checks
apply the engine's builtin/import rules to every module; only the entry module
needs `turn()`. Both trial sides stage the exact same captured file dictionary.
Verdicts bind the complete digest, latest-valid activation stays unchanged, and
pin/start/download integrity checks cover every helper and dependency.

`registry.submit_bundle` is the explicit entry; `download_bundle` checks scope
and returns a reproducible ZIP with sorted members and fixed metadata.
The export includes `requirements.json` when the bundle declares a dependency.
That preserves the original exact pins while allowing a bundle with 32 Python
files and zero dependencies to be uploaded again within the same file limit.
A bundle cannot be mislabeled as a single-file source download with a
package-wide hash. Staff reads are audited. The HTTP
upload endpoint queues the existing two-sided check; worker behavior is the
same as for single-file bots.

Engine semantics: imports execute modules again rather than using Python's
usual module cache; cyclic imports fail; only flat absolute imports work.
Helpers inherit the engine's game builtins, including controller operations.
Documented native behavior is from the installed engine source and verified by
real two-sided trial games, not a simulated replacement engine.
